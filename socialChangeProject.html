How to use Problem Map Builder

Building

  • The dark box in the middle is your problem statement. Double-click it to write it, and draw arrows to or from it like any other node.
  • Add nodes with the toolbar (or keys N node, S section). Double-click empty canvas to add a node there. Each node's color shows which of the six subsystems it belongs to.
  • Draw arrows: hover a box and drag its ⊕ dot onto another box. Drop on empty space to create a new connected box. Or turn on Connect mode (C) and click two boxes.
  • Write on arrows: double-click an arrow (or select it and click ✎ add text) and type. Press Enter to finish, ⇧ Shift+Enter for a new line. You can also edit the text in the right panel.
  • The toolbar's "New arrows are" setting picks the arrow type. You can change any arrow's type later by clicking it.
  • Section boxes label regions of the map (e.g. "History", "Future: Health"). Dragging a section by its title moves the boxes inside it too (hold ⌥ Option/Alt to move only the section).
  • Arrows between the same two boxes curve apart automatically; use the Curve slider on an arrow to untangle crossings.

Moving around

  • Drag empty canvas to pan (two-finger scroll also pans). Pinch or ⌘/Ctrl + scroll to zoom. Fit shows everything.

Keyboard

  • Delete removes the selection · ⌘Z undo · ⇧⌘Z redo · ⌘D duplicate box · Esc deselect

Saving

  • Every change is saved automatically in this browser (on this computer). Snapshots are kept in Version history.
  • For extra safety use Download backup, or in Chrome/Edge choose Also auto-save to a file so every change is written to a file too.
  • Browsing in private/incognito mode does not keep saves after closing the window.

Assignment checklist

The left panel checks your map against the assignment requirements as you build (feedback loop, dated history, sources, dead ends, disconnected pieces...). Click an item with Show to jump to the box that needs work.

Version history

Snapshots are taken automatically every few minutes while you work, and before big actions (opening a backup, starting a new map, restoring).

Publishing setup (one time)

To put your map on the website, this page saves it as problemMap.json in your GitHub repo. GitHub needs a key (a “token”) that lets it do that. The key is stored only in this browser. It is never put in the website’s code, so nobody else can publish.

  1. Open github.com/settings/personal-access-tokens/new (sign in if asked).
  2. Name it “Problem map”. Set Expiration to a date after your assignment is due.
  3. Under Repository access choose Only select repositories → molly-culot.github.io.
  4. Under Permissions → Repository permissions set Contents to Read and write.
  5. Click Generate token, copy it, and paste it below.
